# コメント機能の手動受入

P3-1〜P3-4 の実装後に、運営者が実際の操作を確認するための手順です。自動検証の成功と手動受入は別に記録します。以下のチェックはすべて **未実施** の状態です。確認した項目だけチェックしてください。

## 1. ローカル試用を起動する

本番用の起動とは別のターミナルで、リポジトリ直下から実行します。Node.js 24 を使用してください。

```powershell
npm ci
npm run preview:discussion
```

`preview:discussion` はビルド後、コメントを有効にした独立プロセスを `127.0.0.1:3001` に起動します。通常の `npm start` は従来どおり3000番で、コメント無効のままです。Node.js 24 が標準の `node` でない場合は、次の一時実行も使えます。

```powershell
npm exec --yes --package=node@24 -- npm ci
npm exec --yes --package=node@24 -- npm run preview:discussion
```

- ターミナルに表示された運営用 URL を同じ PC のブラウザで開きます。URL には管理キーを含むため、スクリーンショット・チャット・PR・検証記録に貼らないでください。`ADMIN_KEY` を事前設定した場合、キーは表示されません。表示された `/admin` の末尾に `#` と設定したキーを付けて開きます。
- 公開用の `BASE_URL` または `TRANSPORT=cloudflare` / `https-proxy` が残っていると起動を拒否します。新しい試用用 PowerShell 内だけで `Remove-Item Env:BASE_URL, Env:TRANSPORT -ErrorAction SilentlyContinue` を実行して解除できます。
- 3001番が使用中なら `$env:PREVIEW_PORT = '3002'` で変更できます。`0` は空きポートを自動選択します。通常起動用の `PORT` は試用では参照しません。
- このコマンドに Tunnel を接続しないでください。公開用設定を拒否する仕組みは、別途構成したプロキシの接続をあらゆる方法で防ぐものではありません。
- `Ctrl+C` で終了します。試用プロセスの票・コメント・いいねはメモリだけにあり、再起動では復元されません。

## 2. 確認用の画面を準備する

- [ ] 運営画面の「質問集を読み込む」で [試用質問集](examples/discussion-acceptance-deck.json) を読み込む。単一選択・事前審査・即時公開・複数選択の4件が並ぶ。
- [ ] 「発表画面を開く」で発表用タブを開く。画面共有にはこのタブだけを使う。
- [ ] 「この端末用の参加URLをコピー」で参加用タブを開く。
- [ ] 別のブラウザか別プロファイルでも参加用 URL を開く。同じ通常プロファイル内の複数タブは同じ匿名トークンを共有するため、別参加者の検証には使わない。

実際の投稿や個人情報は使わず、「確認用コメントA」「確認用コメントB」等のダミーで検証します。

## 3. コメントを一巡する

| 確認 | 操作 | 期待する結果 |
| --- | --- | --- |
| [ ] | 事前審査のお題の受付を開始し、参加者Aから投稿 | 運営の承認待ちだけに表示。参加者Bと発表画面には本文が出ない |
| [ ] | 「承認して公開」 | 参加者一覧と発表一覧に表示。本文の `<b>` 等を入力しても HTML として解釈されない |
| [ ] | 参加者Bがいいね→取消→再度いいね | 件数が1→0→1。参加者Aは自分の投稿にいいねできない |
| [ ] | 複数投稿のいいね数を変える | いいね数降順、同数は投稿順。発表順固定中は発表の順だけ維持し、新規公開は末尾 |
| [ ] | 「発表で拡大」→「コメント一覧を発表」 | 対象1件の拡大と一覧に切り替わる。1件でも読みやすい |
| [ ] | 「紹介済みにする」→解除 | 既定では発表一覧から約250msで退場し、残りが滑らかに移動。参加者は引き続き閲覧・いいね可能 |
| [ ] | 「設定・管理」で「紹介済みを一覧から除く」を外す | 紹介済みも発表一覧に残る |
| [ ] | OSの動きを減らす設定を有効にして紹介済み操作 | 退場・移動の演出が省略される |
| [ ] | 注目中の投稿を「非公開」 | 次の更新で参加者・発表から本文が消える。運営では保持され、再公開できる |
| [ ] | 注目中の投稿を削除（キャンセルと確定を両方確認） | キャンセルでは保持、確定では本文といいねが消え、再公開できない |
| [ ] | 「受付を緊急停止」 | 対象のお題の投稿・いいねが止まる。公開一覧の閲覧、運営の審査、書き出しは可能 |
| [ ] | 即時公開のお題で投稿 | 承認なしで公開。上限1件で2件目を拒否 |
| [ ] | 審査方式を途中で切り替える | 以降の新規投稿だけに適用。既存の公開・非公開状態は変わらない |
| [ ] | 通信を切ってから復帰 | 入力中の本文を保持。同じ投稿の再送で重複しない。発表はエラー検出後に表示停止し、復帰後は最新の公開状態を表示 |

非公開・削除前に撮影した内容や、通信断中の画面まで完全に回収することはできません。更新反映までの時間も確認してください。

## 4. 保存・消去・投票の互換性

- [ ] 「公開コメント JSON」で保存の注意を確認する。公開済みだけが `pochipoll-comments.json` に入り、紹介済みは含み、承認待ち・非公開・削除済み本文は含まない。実際に保存先のファイルを開いて確認する。
- [ ] 「質問集 JSON」は設定だけで、投稿本文やいいねを含まない。選択式とお題の並べ替え・再読込でも順序と設定が保たれる。
- [ ] 単一選択・複数選択の投票、回答変更、結果公開・非公開、票リセット、CSV／集計 JSON が従来どおり動く。
- [ ] 「次へ」で選択式とコメントの間を移動できる。ほかのお題の受付状態は勝手に変わらない。
- [ ] 「全データ消去」の確認画面からコメント JSON を保存できる。消去後は質問・票・投稿が消え、古い参加 URL・発表 URL が使えない。
- [ ] 試用を停止・再起動すると投稿が戻らない。ブラウザの控えから復元できるのは質問集の設定だけ。

## 5. 公開経路の確認は別工程

上記はローカルの手動受入です。Cloudflare 経由、スマートフォン、QR、実際の画面共有、複数端末での投票・投稿・いいねは **未確認** として別に残します。ローカル手動受入の結果とレビューを確認してから、コメントを有効にした公開経路の検証方法を決めます。通常起動の機能ゲートを自動では解除しません。

## 結果の記録

記録には日時、環境（OS・Node.js・ブラウザ）、項目番号、成功／失敗、画面上の現象だけを残します。管理キー・各アクセス URL・トークン・実際の投稿内容は記録しません。

```text
確認日：
環境：
ローカル手動受入：未実施 / 一部完了 / 完了
失敗または未確認の項目：
Cloudflare・スマートフォン・画面共有：未実施
```
